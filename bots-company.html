Problems the line is built to eat.

RED bots are kits on a factory — not chat windows with a logo. They take repeatable process work, keep the field dictionary honest, and leave the customer with a demo they can walk. Value is hours back, status that does not drift, and a line that stamps the next bot instead of starting over.

Brochure of the offer. Kits stay in-house. Not a public prompt dump. Not a new repo per customer.

Problems Purchasable Factory

01

what they eat

Problems and value

If the work resets every week, if the fields live in one person’s head, or if each customer becomes another repo — the factory is the fix.

01

Repeat work that does not compound

The same process runs every week in inboxes and spreadsheets. A bot on the line keeps the dictionary, the statuses, and the demo — so the work compounds instead of resetting.

02

A new repo per customer

That is a consultancy with extra tokens, not a factory. One shell stamps many bots. The kit is reusable. The customer’s records are not trapped in a snowflake.

03

Fields living in someone’s head

Excel is the contract. Software matches the dictionary — not the other way around. When the fields move, the kit moves with them.

04

Integrations the model holds

Connectors live in data: auth, map, read, write, replay, audit. Idempotent writes. Queue what cannot finish in a request. The model never holds the raw client.

05

No evals, quiet failure

A kit without evals drifts. Operators cannot see it. Every purchasable bot ships with evals so failure is visible before it is expensive.

06

Nothing sales can walk

Every kit gets a demo URL. The same line the operator lives with is the line the buyer sees. Demos lead. There is no production database invented to look busy.

02

what you buy

A purchasable bot

A kit on the line: process + field dictionary + statuses + integrations + prompt kit + evals + demo URL. You buy that bundle on a named workflow. You do not buy a personality, a public prompt, or the factory source.

A

Process

A named workflow with statuses a person already runs. Not a personality. Not a chat toy.

B

Field dictionary

Canonical fields from paper and Excel. The bot, the demo, and the API speak the same contract.

C

Integrations + evals

Connectors mapped in data. Evals on the kit so drift is a failing test, not a surprise.

D

Demo URL

A walkable proof on the line. First gallery proof: a custom bot website — coming on the Demo Portal.
