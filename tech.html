03

public api

How to use it

JSON in, JSON out. No SDK. Content-Type: application/json. Account routes take Authorization: Bearer. Browser calls work from innovatered.com and rps.innovatered.com. curl and server-to-server work from anywhere. This brochure does not call the API.

# liveness
curl https://red-api-8w9g.onrender.com/health

# contact
curl -X POST https://red-api-8w9g.onrender.com/contact \
  -H 'Content-Type: application/json' \
  -d '{"name":"Alex","email":"alex@site.example","note":"24-device warehouse"}'

# login → token
curl -X POST https://red-api-8w9g.onrender.com/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@site.example","password":"********"}'

# me
curl https://red-api-8w9g.onrender.com/auth/me \
  -H 'Authorization: Bearer '

Errors: 400 missing or invalid fields · 401 missing or bad bearer · 409 email already registered.

04

endpoints

HTTP APIs

Live Flask routes and the planned OpenAPI pair. Open a card for request, response, and fields. GET /health is public.

  • GET/healthlive

    Liveness for the Flask process. Public. No auth.

    Request: None · Response: { "status": "ok", "service": "red-api" }

    Use this as the deploy check. Keep the shape; add a version field only if you need it.

    Open /health →

  • POST/contactlive

    Lead capture. Persists a row; may log or SMTP mail per MAIL_MODE.

    Request: JSON body · Response: { "ok": true, "id": 1, "mail": "log" }. 400 if name/email/note missing.

    • namestringRequired. Trimmed.
    • emailstringRequired. Must look like an email.
    • companystringOptional. Trimmed; omit or empty OK.
    • notestringRequired. Trimmed.

    The Home contact form posts here. Keep those fields aligned with this card.

  • POST/auth/registerlive

    Create an account. Returns a bearer token and user.

    Request: JSON body · Response: 201 { token, user }. 400 validation. 409 duplicate email.

    • emailstringRequired. Normalized lower-case.
    • passwordstringRequired. Min 8 characters.
    • namestringOptional. Trimmed.

    Client stores the token as red_auth_token and sends Authorization: Bearer on later calls.

  • POST/auth/loginlive

    Sign in. Same token + user shape as register.

    Request: JSON body · Response: { token, user }. 401 on invalid credentials.

    • emailstringRequired.
    • passwordstringRequired.

    Same token key as register.

  • GET/auth/melive

    Current user for a valid bearer token.

    Request: Authorization: Bearer · Response: { user }. 401 if missing or invalid.

    Used by the account drawer. 401 should clear the stored token.

  • POST/auth/logoutlive

    Revokes the bearer token server-side.

    Request: Bearer optional; empty JSON body OK · Response: { "ok": true }

    Client always clears red_auth_token after logout, even if the request fails.

  • GET/docsplanned

    Swagger UI — not shipped. Flask has no OpenAPI UI by default.

    This catalog is the contract until we adopt an OpenAPI UI.

  • GET/openapi.jsonplanned

    OpenAPI schema — not shipped on the Flask app.

    Prefer documenting live routes here over a generated file that does not exist.

how we stay exceptional

Craft

Bench rules we actually run. The last 10% is founder-parallel. Kits stay private. Test bots do not write live.

01

Field dictionary is the contract

Excel fields before tables. SQLAlchemy matches the dictionary. Postgres waits.

02

One engine

New tables reuse the SQLAlchemy engine. No second data layer. No Mongo because it is flexible.

03

Mapping in data

Connectors: auth, map, read, write, replay, audit. The model never holds raw SaaS clients.

04

Idempotent writes

Queue what cannot finish in a request. Unique external_id. JSONB for raw payloads.

05

Public pages do not carry kits

Brochure shows the HTTP surface and the factory line. Coverage algorithms, file formats, and engine internals stay in-house.
